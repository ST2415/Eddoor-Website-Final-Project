# 🚀 Git & GitHub Collaboration Guide for Team
คู่มือและข้อปฏิบัติเบื้องต้นสำหรับการใช้ Git ทำงานโปรเจกต์กลุ่ม เพื่อป้องกันปัญหาโค้ดตีกัน (Merge Conflict) และช่วยให้การรวมโค้ดราบรื่นที่สุด📌 



## 0. ดึงโค้ดและเตรียมเครื่อง (Setup Phase)

1. ดึงโค้ดลงเครื่องของแต่ละคน (Clone)
   ```bash
   git clone https://github.com/ST2415/Eddoor-Website-Final-Project.git
   cd <ชื่อโฟลเดอร์โปรเจกต์ (ถ้าอยากเอาไปใส่ในโฟลเดอร์ไหน)>
   ```
2. สร้าง Branch ใหม่และสลับเข้าไปทำงานทันที: (แนะนำให้ใช้คำสั่งนี้เวลาเริ่มทำฟีเจอร์ใหม่)
  ```bash
   git checkout -b feature/ชื่อฟีเจอร์หรือชื่อหน้า
   ```

3. **(สำคัญ) ดึงข้อมูลล่าสุดจาก GitHub ของเพื่อนมาไว้ที่เครื่องเรา: (ควรทำก่อนเริ่มเขียนโค้ดทุกวันและพยายามทำทุกๆ 1-2 ชม.)**
  ```bash
   git pull
   ```

4. ส่งโค้ดขึ้น GitHub ของตัวเอง:
   ```bash
   git add .
   git commit -m "finish my assigned pages"
   git push origin <ชื่อ Branch ของตัวเอง>
   ```



## 1. คำสั่ง Git พื้นฐานที่ทุกคนต้องรู้ (Cheat Sheet)

- เช็คว่าตอนนี้เราอยู่ Branch ไหน:
  ```bash
   git branch
   ```

- สลับไปมาระหว่าง Branch:
  ```bash
   git checkout ชื่อกิ่งที่ต้องการไป
   ```

- ส่ง Branch ของเราขึ้นไปเก็บบน GitHub: (ทำครั้งแรกเมื่อสร้าง Branch ใหม่)
  ```bash
   git push -u origin ชื่อกิ่งของเรา
   ```

- สลับกลับไปที่กิ่ง main เพื่อดึงโค้ดล่าสุดของเพื่อนมาก่อน:
  ```bash
   git checkout main
   git pull
   ```

- สลับกลับมาที่กิ่งของเรา แล้วดึงโค้ดล่าสุดจาก main มาอัปเดตในกิ่งตัวเอง:
  ```bash
   git checkout feature/ชื่อกิ่งของเรา
   git merge main
   ```

- เช็คสถานะปัจจุบันของไฟล์:
  ```bash
   git status 
   ```

- บันทึกการเปลี่ยนแปลง (Commit) ของตัวเอง:
  ```bash
   git add .
   git commit -m "ข้อความอธิบายสิ่งที่ทำ เช่น add homepage layout"
   ```

- ส่งโค้ดขึ้น GitHub
  ```bash
   git push origin ชื่อกิ่งก้าน (branch) ของตัวเอง
   ```
    


## 🔀 2. ระบบ Branch (กิ่งก้านสาขา) กฎเหล็กเพื่อไม่ให้โค้ดพัง

เพื่อไม่ให้ทุกคนเขียนทับไฟล์เดียวกันจนพัง แนะนำให้แบ่ง Branch ตามหน้าเว็บหรือหน้าที่รับผิดชอบ:

- main หรือ master $\rightarrow$ กิ่งหลักสำหรับรวมโค้ดที่สมบูรณ์และพร้อมส่งงานเท่านั้น (ห้ามมาเขียนทับตรงนี้โดยตรง)
- feature/home $\rightarrow$ สำหรับคนที่ทำหน้า Home
- feature/content $\rightarrow$ สำหรับคนที่ทำหน้า Content (Activity 2 หน้า)
- feature/contact $\rightarrow$ สำหรับคนที่ทำหน้า Contact และ Feature
- feature/trade $\rightarrow$ สำหรับคนที่ทำหน้า Trade และ Feature

วิธีสร้างและสลับไป Branch ของตัวเอง:
```bash
   git checkout -b feature/ชื่อหน้าของตัวเอง
   ```



## ⚠️ 3. ข้อควรระวังและวิธีป้องกันปัญหา (Best Practices for Team)
1. **ห้าม แก้ไฟล์, Commit และ Push ทับไฟล์กลางพร้อมกัน:** ไฟล์ที่เป็นส่วนกลาง เช่น Navbar, Footer หรือไฟล์ตั้งค่าโปรเจกต์ ควรให้คนที่เป็นหัวหน้าทีม (Tech Lead) หรือผู้รับผิดชอบโครงสร้างหลัก เป็นคนสร้างและอัปเดตขึ้นคนแรก จากนั้นให้เพื่อนคนอื่นใช้คำสั่ง git pull ดึงไปใช้ต่อ ห้ามสร้างซ้ำเอง
2. **ดึงโค้ดล่าสุด (Pull) ก่อนเริ่มงานเสมอ:** ก่อนจะนั่งเขียนโค้ดใหม่ทุกครั้ง ให้รันคำสั่ง git pull เพื่อให้แน่ใจว่าเครื่องเรามีโค้ดเวอร์ชันล่าสุดจากเพื่อนร่วมทีมแล้ว
3. **แยกไฟล์ CSS / Component ของใครของมัน:** เพื่อป้องกันการแก้โค้ดทับกัน ให้แยกไฟล์สไตล์หรือไฟล์ย่อยตามหน้าเว็บที่รับผิดชอบ (เช่น home.css, content.css, contact.css)
4. **ไฟล์ generals.css เป็น CSS กลาง :** ถ้าต้องการดึงหน้าตา Navbar, Footer หรือค่าอื่นๆ เช่น root (ค่าตัวแปล/variables) ที่มีเหมือนกันทุกๆ หน้าให้มาเรียกใช้จากไฟล์นี้
5. **ถ้าเกิด Merge Conflict (โค้ดตีกัน) ต้องทำอย่างไร?** 
   - ตั้งสติ อย่าเพิ่งตกใจ
   - Git จะแจ้งเตือนว่าไฟล์ไหนที่มีปัญหา ให้เปิดไฟล์นั้นขึ้นมาดู จะเห็นสัญลักษณ์ <<<<<<<, =======, >>>>>>>
   - พูดคุยกับเพื่อนในทีมว่าต้องการเก็บโค้ดส่วนไหนไว้ แล้วลบบรรทัดที่เป็นสัญลักษณ์ออกให้เรียบร้อย
   - ทำการ git add . $\rightarrow$ git commit $\rightarrow$ git push อีกครั้ง
